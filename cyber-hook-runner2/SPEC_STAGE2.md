# 第2段階：ヴォイドウェーブ（追跡者）と適応BGM

## 0. この文書の位置づけ

同じフォルダの index.html（Ver 4.0 第1段階：移動の感触とパルスバッシュ）を土台にした、第2段階の実装指示書。読み手は Claude Code。
最終目標は「動かしているだけで気持ちいい」の一点で、『Ori and the Will of the Wisps』の逃走シーンを超えること。Oriの逃走シーンは固定コースの暗記型。本作は毎回自動生成されるコースを、追跡者に追われながら初見で駆け抜ける形で差別化する。物語や美術の総量では勝負しない。

## 1. 前提と制約

単一HTMLファイル構成を維持。Phaser 3.60.0（CDN読み込み）と Web Audio API のみを使い、外部の画像・音源は使わない。論理解像度は 960×600、Scale.FIT。
localStorage キー cyberHookHighScore2 と cyberHookStats2 は互換を維持する。新しい項目の追加は可、既存項目の意味を変えるのは不可。
タッチ、マウス、キーボードの3系統で同等に遊べることを維持。
既存の調整定数（BOOST、BASH_V、HOOK_RANGE など）は本書で指定したもの以外は変更禁止。変更が必要と判断した場合は、理由を添えて報告し、承認を得てから変更する。
ファイル先頭のコメントに CHANGELOG 欄を設け、版ごとの変更点を記録する。

## 2. 作業0：現行コードの動作検証（最優先）

Ver 4.0 はブラウザでの実行確認が済んでいない。新機能に着手する前に、ローカルサーバー（npx http-server または python3 -m http.server）で起動し、コンソールエラーがないか確認する。可能なら Playwright などのヘッドレスブラウザで起動確認とスクリーンショット取得まで行う。

確認すべき挙動は次のとおり。初回タップで第1アンカー(330,150)へ確実にフックできること。押しっぱなしで射程内のアンカーへ自動でフックできること。振り子の最下点が床から75px以上の上空に保たれること。床に触れたときに即死せず、HP減少と上空へのバウンドが起きること。光の種、ミサイル、レーザー核の115px以内での押下でパルスバッシュ（0.05倍スロー、照準、射出）が成立すること。BASH LINK と FLOW CHAIN の得点が入ること。リザルト画面からのリトライが1.2秒以内に可能なこと。

コードレビュー時点で疑いのある箇所（いずれも未確定）を挙げる。

1つ目はバッシュ優先問題。光の種の近くでは、押下がフックよりバッシュを優先する。アンカーをつかみたい場面で意図せずバッシュが発動するおそれがある。実際に遊んで問題が確認された場合は、「進行方向前方220px以内にロックオン可能なアンカーがあり、かつバッシュ対象がプレイヤーより後方にある場合はフックを優先」という規則を候補として提案する。

2つ目はミサイルの出現位置。camX−60 での出現は、ズーム0.94のときに画面内で突然現れる可能性がある。ズームを考慮した表示範囲の左端の外側から出現させる補正が必要か確認する。

3つ目は再フック猶予。リリース後0.22秒間、後方220pxまで探索範囲を広げているため、通過済みのアンカーへ引き戻される誤フックが起きないか確認する。

4つ目は勢い保存の暴走。ロープが強く張ったときに速度の9割を接線方向へ移す処理（SNAP_KEEP）が、ループを繰り返すことでエネルギーを増やし続けていないか確認する。VMAX で上限はかかるが、1250px/s に張り付き続ける場合は要報告。

5つ目は性能。Graphics の毎フレーム全再描画と加算合成レイヤーで、モバイル端末でも60fpsを維持できるか確認する。

不具合の修正は最小限の差分で行い、修正内容を一覧にして報告してから第2段階に進む。

## 3. 第2段階の目的

画面左から迫る闇の波「ヴォイドウェーブ」を追加し、ゲーム全体を「毎回生成される逃走劇」へ変える。上手く動くほど波を引き離せて、音楽が完成していく。遅れるほど音がこもり、心音が迫ってくる。操作の上手さ、緊張感、音楽の高揚を1本の線でつなぐことが本段階の核心。

## 4. ヴォイドウェーブ仕様

### 4.1 位置と速度
波の先端X座標 waveX と、プレイヤーとの距離 gap = px − waveX で管理する。
開始時は waveX = px − 1000。最初の入力から5秒間は静止する猶予期間とし（アシストモードでは7秒）、その後3秒かけて目標速度まで加速する。
目標速度 V_wave は、直近20秒のプレイヤー水平速度の移動平均 avgVx に 0.88 を掛けた値を基準にする。下限は区画ごとに 300 / 340 / 380 / 430 px/s、上限は 1000 px/s。速く走るプレイヤーほど波も速くなるが、平均を保つ限り少しずつ引き離せる設計。
ラバーバンドとして、gap が 1300 を超えたら 1100 に戻るまで速度を1.6倍にし、波が意味を失わないようにする。アシストモードでは最終速度を0.9倍にする。
速度変化は急変させず、毎秒最大 400px/s² で目標値へ近づける。

### 4.2 押し返し
技を決めると波を後方へ押し返す。PERFECT で 60px、LOW POINT で 80px、パルスバッシュで 140px、LOOP で 120px、FLOW CHAIN で 320px。押し返しは0.3秒かけて滑らかに適用する。押し返し後の gap が 1400 を超える分は切り捨てる。
押し返しの瞬間には、プレイヤーから左へ光の衝撃波（半円の広がるリング）を描画する。

### 4.3 接触
gap が PR（14px）以下になったら接触とする。HP を1減らし、無敵時間1.6秒、vx = max(vx, 700)、vy = −650 を与え、waveX を px − 600 まで押し戻す。接触でコンボと LINK 状態は消える。HP が0になった場合の死因コードは void とする。
CAUSE_JP に「void: ヴォイドウェーブに呑まれた」を、ADVICE に「void: 技を決めるほど波は退く。FLOW CHAIN で大きく押し返そう」を追加する。

### 4.4 危険域と脱出
gap 600未満を警戒域、250未満を危険域とする。危険域に入ったあと gap 700以上まで回復した場合は「ESCAPE +200」を成立させ、専用の効果音とスタンプを出す。この判定は危険域に入るたびに1回だけとする。

### 4.5 カメラ補正
現在のカメラはプレイヤーを画面左から約300pxの位置に置くため、gap が300を超えると波が画面に映らない。そこで gap が700未満のとき、カメラの目標オフセットを 300 から 420 へ、gap に応じて線形に移す。これで背後の視界を広げる。補正値の変化は Lerp で滑らかにする。

### 4.6 描画
波の先端は縦方向に並ぶ複数のサイン波を重ねた揺らぐ境界線とし、本体は #05010a、縁の発光は #7a3cff を加算合成で描く。先端から左後方へ流れる黒紫の粒子と、前方へ伸びる触手状の曲線（3〜5本、gap が近いほど長い）を描く。
画面外にいるときも存在がわかるように、gap 900未満で画面左端に闇のにじみ（左から右へのグラデーションの黒）を表示する。強さは gap に反比例させる。
波より後ろにある背景の窓明かりと光の粒は消灯させ、「光を呑む闇」を表現する。
この描画には新しい Graphics レイヤー gVoid を使い、メインカメラに属させる。UIカメラからは除外する。

## 5. プラズマ床の扱い（設計案からの変更点）

前回の設計案では床を波に置き換える予定だった。しかし床は「ワイヤー長の自動制限」と「バウンドによる救済」の基準になっているため、本段階では床を残す。床と波の二重の圧力が厳しすぎる場合は、床接触時のダメージを無効化し、バウンドのみにする選択肢を残す。この判断は試遊結果を報告してから行う。

## 6. 適応BGM仕様

### 6.1 全体構造
現在の単一シーケンサーを、レイヤー別のシーケンサーに作り替える。各レイヤーは専用の GainNode を持ち、全レイヤーはローパスフィルター（BiquadFilter）を通って bgm バスへ合流する。BPM は 132 を維持。音階は A マイナーペンタトニック（A C D E G）とし、既存の synth.root による区画ごとの移調を引き継ぐ。移調は次の小節の頭で適用する。
和音進行は4小節ループで Am、F、C、G（root からの相対）。

### 6.2 光量ゲージ「ルミナ」
0〜100 のゲージで、音楽の完成度を決める。上昇要因は、水平速度700px/s以上で毎秒+6、PERFECT +4、LOW POINT +6、トリック +5、バッシュ +8、BASH LINK +10、LOOP +10、FLOW CHAIN +20、ESCAPE +12。減少要因は毎秒−3の自然減衰と被弾時の−30。

### 6.3 レイヤー
ルミナ0（AMBIENT）はパッド和音（三角波2〜3音、ゆっくり開くフィルター）とペンタトニックの柔らかいアルペジオ。ルミナ20（PULSE）でキック、40（DRIVE）でベース、60（RUSH）でハイハットとスネア、80（RADIANT手前）でリード旋律を追加する。ルミナ100の RADIANT では対旋律を加え、5秒間すべてのテクニック得点を1.5倍にする。RADIANT 終了後、ルミナは70に戻る。
レイヤーの追加と除去は必ず小節の頭で行い、1拍かけてフェードさせる。しきい値の上下で頻繁に切り替わらないよう、5ポイントの余裕（ヒステリシス）を設ける。

### 6.4 危険オーバーレイ
gap に連動して、ルミナとは独立した緊張要素を重ねる。gap 600未満で低いドローン音（ノコギリ波55Hz、ローパス通過）がフェードインする。gap 300未満で心音（60Hzのサイン波2連打）が鳴り、テンポは gap に応じて毎分90から150へ上がる。さらに gap 600から0にかけて、BGM全体のローパスの遮断周波数を 18000Hz から 1200Hz まで下げ、「呑まれかけて音がこもる」状態を作る。ESCAPE 成立時は遮断周波数を0.4秒で全開に戻し、上昇音のスティンガーを鳴らす。

### 6.5 効果音の音階統一
フック、コイン、PERFECT、FLOW CHAIN の音程を、現在の root を基準にしたペンタトニック音階の音に揃える。コイン音はコンボ数に応じて音階を1段ずつ上がる（2オクターブで折り返し）。発音タイミングは入力の瞬間のままとし、拍への吸着はしない（反応速度を優先）。

### 6.6 実装上の注意
BGM の発音は効果音の同時発音数制限（8音）の対象外。ただし BGM 用に生成する OscillatorNode は必ず stop と disconnect を行い、ノードの解放漏れを防ぐ。先読みスケジューラー方式（25ms周期、0.12秒先読み）は維持する。シーン再起動のたびにタイマーを重複して生成しないこと。死亡時は0.4秒で全体をフェードアウトし、リトライで AMBIENT から再開する。

## 7. UI追加

画面上部中央に、ヴォイドとの距離を示す横長メーター（幅300px）を置く。0〜1400 の gap を表示し、警戒域は紫、危険域は赤く点滅させる。メーターの右に「VOID 42m」の形式で距離を表示する（gap ÷ 10）。
画面右下にはルミナゲージを置き、レイヤーの区切り位置に目盛りを付け、現在の段階名（AMBIENT / PULSE / DRIVE / RUSH / RADIANT）を表示する。RADIANT 中はゲージ全体を白く脈動させる。
既存のコンボ表示とメーター表示が重ならないよう、コンボ表示は Y=90 へ移す。

## 8. スコアとミッションの追加

得点に ESCAPE（+200）を追加し、リザルトの内訳に「ESCAPE 回数」「最大 gap」「RADIANT 到達回数」を加える。
ミッションの抽選候補に「ヴォイドを10回押し返す」「RADIANT に到達」「危険域から2回脱出」「ヴォイドに一度も触れずに800m」を追加する。
統計に voidContacts（累計接触回数）を追加する。

## 9. ディレクターAIとの連動

ヴォイドの下限速度に、難易度係数 k による補正（+60k px/s）を加える。直近3ランの平均距離が250m未満のアシストモードでは、猶予期間の延長と速度0.9倍に加え、押し返し量を1.25倍にする。直近10ランで死因 void が5回以上の場合は、次のラン冒頭のアドバイスを void 用に切り替える。

## 10. デバッグ機能

URL に ?debug=1 を付けた場合のみ、画面左下に fps、gap、V_wave、avgVx、ルミナ、現在のレイヤー、k、アシスト状態を表示する。デバッグ時のみ有効なキーとして、I（無敵の切り替え）、V（波の停止）、L（ルミナ+20）、N（次の区画の手前へワープ）を追加する。ワープ時は周辺のオブジェクトを破棄し、ワープ先からチャンクを再生成する。通常起動時はこれらを一切無効にする。

## 12. 受け入れ基準

最新の Chrome、Safari、Firefox でコンソールエラーがないこと。中程度のPCで60fps、近年のスマートフォンで50fps以上を維持すること。第1段階の機能がすべて従来どおり動くこと。
初めて遊ぶ人が、最初のヴォイド接触までに平均20秒以上生き残れること。上手いプレイヤーが技の連携で gap 700以上を維持し続けられること。BGM レイヤーの切り替えが小節の頭で、ノイズなく行われること。10回連続でリトライしても、AudioNode とメモリ使用量が増え続けないこと。リザルトからのリトライが1.2秒以内に可能なこと。
自動テストが可能な範囲（起動、エラーなし、デバッグ表示の数値変化）は Playwright で検証し、手触りに関わる部分は人間の試遊項目として報告にまとめる。

## 13. 範囲外（後続段階）

第3段階は光の演出。手前・中間・奥の3層シルエット、プレイヤーを光源とする周辺照明、逆光表現を予定。第4段階は物語の断片で、区画突破ごとに一文の散文詩を挟む。重力反転パッドは引き続き保留。本段階ではこれらに手を付けないが、描画レイヤーの分離など、後続段階を妨げない構造にしておくこと。
